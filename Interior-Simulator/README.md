# Interior Simulator

[![CI](https://github.com/jhpark-coder/interior-simulator/actions/workflows/ci.yml/badge.svg)](https://github.com/jhpark-coder/interior-simulator/actions/workflows/ci.yml)

평면도 이미지를 바탕으로 집 구조를 만들고, 가구 배치와 3D 공간을 비교하며,
사진·메모를 위치와 함께 기록하는 로컬 우선 웹 애플리케이션입니다.

현재 코드는 기능 검증 단계의 베타입니다. 합성 fixture와 자동 테스트는 통과하지만,
다양한 실제 부동산 평면도에 대한 인식 정확도와 신규 사용자 작업 시간은 별도
수용시험이 필요합니다.

## 핵심 작업 흐름

화면 상단의 3단계를 순서대로 진행합니다.

1. **집 구조**
   - JPG·PNG 또는 PDF의 한 페이지를 평면도 레이어로 불러옵니다.
   - 평면도의 치수선 두 점과 실제 길이로 축척을 맞춥니다. 흐린 평면도는 밝기·대비·흑백으로
     보기 좋게 보정합니다(화면 표시용).
   - `영역 자르기`로 표제란·범례 같은 필요 없는 부분을 가립니다. 원본은 그대로 두며 자동
     인식도 남긴 영역만 분석합니다.
   - 벽·문·창문·통로(문 없는 출입구)를 직접 그립니다. L자형, 다중 벽, 다중 방 구조를
     편집할 수 있습니다.
   - 벽 길이를 숫자로 입력하고, `벽 일괄 변경`으로 모든 벽 또는 외벽·내벽·가벽의 두께·높이를
     한 번에 바꿉니다.
   - 문을 선택하면 여닫이·미닫이, 경첩 위치, 열리는 쪽(방 안쪽·바깥쪽), 열림 각도를 고칩니다.
     2D에는 문짝과 열림 범위(호)가, 미닫이문은 미는 방향이 표시됩니다.
   - 자동 인식(벽·문·OCR 후보)은 접힌 `자동 인식 (실험 기능)` 섹션에 있습니다.
   - 평면도가 없으면 `샘플 구조`에서 84㎡ 방 3개 아파트, L자형, 방 3개 예시를 불러옵니다.
2. **가구 배치**
   - 가구·가전·수납·설비 객체를 배치합니다.
   - 캔버스 상태줄의 `통행 폭`을 켜면 가구 사이, 가구와 벽 사이의 좁은 틈(600mm 미만 빨강,
     900mm 미만 주황)을 치수와 함께 보여 줍니다.
   - 상단 `배치안` 메뉴로 여러 배치안을 만들고 비교합니다.
   - 벽·바닥·천장·문·창문의 색상 재질을 배치안별로 관리합니다.
3. **구경하기**
   - 가구를 배치한 공간을 3D 전체 화면으로 둘러봅니다.
   - Orbit 및 1인칭 이동을 지원합니다.
   - 문과 창문을 클릭하면 열고 닫힙니다. 가구에 막힌 문은 닿기 직전까지만 열립니다.

헤더 오른쪽의 2D·Split·3D 토글은 어느 단계에서나 쓸 수 있습니다.

### 보조 기능 (`더보기` 메뉴)

- **백업**: `.interior-project` 패키지 내보내기·열기
- **구조 리비전**: 구조 스냅샷 저장·전환·이름 변경
- **호환 JSON**: 구형 LayoutDoc 내보내기·가져오기
- **공간 기록**
  - 도면 위에 기록 핀을 추가하고 사진·메모·촬영일·방향을 연결합니다. 촬영 방향은 2D
    도면에 부채꼴로, 3D 공간 기록에 방향 표시로 나타납니다.
  - 과거·현재·계획 상태와 저장된 3D 시점을 관리합니다.

## 실행

### 요구 환경

- Node.js `^20.19.0` 또는 `>=22.12.0`
- npm

### 설치 및 개발 서버

```bash
npm install --legacy-peer-deps
npm run dev
```

기본 접속 주소는 `http://localhost:5173`이며, 포트가 사용 중이면 Vite가 다음 포트를
표시합니다. Windows PowerShell 실행 정책으로 `npm.ps1`이 차단되면 같은 명령을
`npm.cmd`로 실행할 수 있습니다.

### 검증 명령

```bash
npm run lint
npm run test:run
npm run test:e2e
npm run build
npm run preview
```

개발 중 테스트 감시는 `npm run test`, Vitest UI는 `npm run test:ui`를 사용합니다.

`npm run test:e2e`는 production 빌드를 `http://localhost:4173`에 띄워 `e2e/`의
Playwright 테스트를 실행합니다. 처음 한 번은 브라우저를 설치해야 합니다.

```bash
npx playwright install chromium
```

브라우저를 내려받을 수 없는 환경에서는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`에 설치된
Chromium 경로를 지정합니다.

GitHub Actions(`.github/workflows/ci.yml`)가 `main` 푸시와 PR마다 `npm ci --legacy-peer-deps`로
새로 설치한 뒤 lint·단위 테스트·빌드와 E2E를 실행합니다. E2E가 실패하면 실행 화면의
`playwright-report` 아티팩트에서 보고서·스크린샷·trace를 내려받을 수 있습니다.

## 사용 순서

### 평면도에서 구조 만들기

1. `1 집 구조` 단계의 `① 평면도 불러오기`에서 JPG, PNG 또는 PDF를 선택합니다.
2. PDF가 여러 페이지면 평면도가 있는 페이지 번호를 선택합니다. 필요 없는 부분이 많으면
   `영역 자르기`를 누르고 캔버스에서 남길 영역의 두 모서리를 클릭합니다.
3. `② 축척 맞추기`에서 치수선 양 끝을 클릭하고 실제 길이를 입력합니다.
4. `③ 벽·문·창문 그리기` 도구로 직접 추적합니다. 문 없는 출입구는 `통로` 도구로 답니다.
   필요하면 `자동 인식 (실험 기능)`으로 후보를 검토합니다.
5. 벽을 선택해 `길이 (mm)`에 값을 넣고 Enter를 누르면 시작점을 기준으로 길이가 바뀝니다.
   여러 벽의 두께·높이는 구조 속성 아래 `벽 일괄 변경`에서 바꿉니다.
6. 구조 오류 목록에서 열린 끝점, 교차, 잘못된 개구부를 수정합니다.
7. 3D 또는 분할 화면에서 구조를 확인합니다.

### 배치안 비교

1. `2 가구 배치` 단계에서 팔레트의 가구를 추가합니다.
2. 가구를 선택·이동·회전하고 우측 인스펙터에서 수치를 조정합니다. `복제`로 옆 빈자리에
   같은 가구를 놓고, `잠금`으로 옮기거나 지우지 못하게 고정합니다.
3. 상단 `배치안` 메뉴에서 새 배치, 복제, 전환, 삭제를 수행합니다.
4. 구조를 바꾼 경우 `더보기 → 구조 리비전 → 현재 구조 저장`으로 리비전을 만든 뒤
   배치안에 연결합니다.
5. 구조를 바꿔 벽 밖에 있거나 벽을 가로지르게 된 가구, 문이 열리는 범위를 막는 가구는
   우측 `배치 검토`에 모이고 캔버스에 빨간 점선으로 표시됩니다. 막힌 문은 문짝과 열림
   범위가 빨갛게 바뀌고 몇 도까지 열리는지 알려 줍니다. 목록을 눌러 선택한 뒤 옮깁니다.
6. 동선이 걱정되면 캔버스 상태줄의 `통행 폭`을 켜서 좁은 곳을 확인합니다.
7. `3 구경하기`로 배치 결과를 3D로 둘러봅니다.

### 공간 기록

1. `더보기 → 공간 기록 열기`로 들어가 기록 핀 도구를 켜고 도면 위치를 클릭합니다.
2. 제목·메모·촬영일·방향을 입력하고 사진을 추가합니다.
3. 필요한 위치를 3D 시점으로 저장합니다.
4. 검색어나 방 필터로 기록을 다시 찾습니다.

## 저장과 파일 형식

- 프로젝트 메타데이터와 사진·평면도 Blob은 브라우저 IndexedDB에 저장됩니다.
- 프로젝트는 5초 간격으로 자동 저장되며, 탭을 숨기거나 닫을 때도 바로 저장합니다.
  새 프로젝트 생성·다른 프로젝트 열기·패키지 가져오기 전에도 현재 프로젝트를 먼저
  저장합니다.
- `더보기 → 백업 파일로 내보내기` 또는 `Ctrl/Cmd + S`는 전체 데이터가 포함된
  `.interior-project` 패키지를 만듭니다.
- `.interior-project` 패키지는 `project.json`과 `assets/` 파일을 포함합니다.
- `더보기 → 호환 JSON 내보내기`는 현재 배치의 구형 `LayoutDoc` 호환용입니다.
  전체 백업에는 사용하지 마세요.
- `구형 JSON 가져오기`는 LayoutDoc v1.1/v1.2를 현재 v2 프로젝트 구조로 변환합니다.

중요한 작업은 브라우저 저장소만 믿지 말고 `.interior-project` 패키지로 별도
백업하는 것을 권장합니다.

## 주요 단축키

- `Delete` / `Backspace`: 선택한 가구(가구 배치) 또는 벽·문·창문(집 구조) 삭제
- `Ctrl/Cmd + D`: 선택한 가구 복제
- `Ctrl/Cmd + Z`: 실행 취소
- `Ctrl/Cmd + Shift + Z`: 다시 실행
- `Ctrl/Cmd + S`: 전체 프로젝트 패키지 저장
- 마우스 휠: 캔버스 확대·축소

가구 단축키(삭제·복제·실행 취소)는 가구 배치 단계에서만 가구에 적용됩니다. 집 구조
단계의 실행 취소는 구조 편집만 되돌립니다. 입력 필드나 메모 편집 중에는 삭제·복제·실행
취소 단축키가 동작하지 않고, 잠긴 가구는 지워지지 않습니다.

## 개인정보와 네트워크

- 평면도와 사진은 기본적으로 브라우저 로컬 저장소에서 처리합니다.
- 기본 선분 인식은 Web Worker에서 로컬 실행됩니다.
- 선택적 OCR은 Tesseract.js 언어 데이터를 최초 실행 시 내려받지만, 평면도 이미지를
  원격 인식 서버로 전송하지 않습니다.
- 3D 조명용 환경맵은 앱에 포함되어 있어 3D 화면은 인터넷 연결 없이 동작합니다.
- 현재 클라우드 동기화나 공유 링크 기능은 없습니다.

## 현재 제한

- 반자동 인식은 선명한 직교형 합성 평면도와 유사한 자료를 기준으로 검증했습니다.
- 실제 평면도 10~20개 기준 precision/recall과 84㎡급 수동 추적 시간은 미측정입니다.
- PDF 전체를 동시에 프로젝트에 넣지 않고 사용자가 선택한 한 페이지를 렌더링합니다.
- 브라우저나 기기가 강제 종료되면 마지막 자동 저장(최대 5초 전) 이후의 편집은 잃을 수
  있습니다. 탭을 정상적으로 닫거나 숨기면 그 시점에 저장합니다.
- 통행 폭은 가구 바닥 면적 기준의 직선 거리입니다. 사람이 실제로 지나가는 경로나
  높이(벽걸이 가구 아래 공간 등)는 고려하지 않습니다.
- E2E는 핵심 흐름과 주요 편집 기능을 Chromium에서 확인합니다. 2D/3D 시각 회귀, 모바일
  사용성, PWA/데스크톱 패키징은 아직 완료되지 않았습니다.
