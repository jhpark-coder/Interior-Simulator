# 평면도 기반 3D 공간 기록·시뮬레이션 구현 상태

기준일: 2026-10-23

이 문서는
[`FLOORPLAN_TO_3D_DEVELOPMENT_PLAN.md`](./FLOORPLAN_TO_3D_DEVELOPMENT_PLAN.md)의
계획과 현재 코드·자동 테스트·수동 검증 범위를 연결한다.

현재 판정은 **기능 검증 단계의 베타**다. 핵심 코드 경로와 자동 검증은 구현됐지만,
실제 평면도 정확도, 신규 사용자 작업 시간, 모바일, 배포 패키지와 전체 E2E는
출시 수용시험으로 남아 있다.

## 구현된 전체 흐름

다음 흐름이 하나의 로컬 웹 앱에 연결되어 있다.

> JPG·PNG 또는 PDF 페이지 선택 → 축척 교정 → 수동 추적 또는 반자동 후보 검토 →
> 구조 수정 → 3D 생성 → 가구와 마감재 배치안 비교 → 사진·메모·촬영 방향 기록 →
> 1인칭 재방문 → 로컬 저장과 프로젝트 패키지 복원

프로젝트 메타데이터와 Blob은 IndexedDB에 저장된다. 기본 평면도 분석은 Web
Worker에서 실행된다. 선택적 OCR은 최초 실행 시 Tesseract 언어 데이터를
내려받지만 평면도 이미지를 원격 인식 서버로 전송하지 않는다.

## 개선 1단계: 화면 정리 (2026-10-21)

설계 근거는 로컬 문서 `docs/superpowers/specs/2026-10-21-kreativ-direction-design.md`다.

- 상단 작업 공간 탭을 3단계 스텝(집 구조 → 가구 배치 → 구경하기)으로 교체했다.
- 공간 기록, 백업 패키지, 구조 리비전, 호환 JSON을 `더보기` 메뉴로 옮겼다.
  코드와 데이터는 유지했다.
- 시뮬레이션 툴바 줄을 없애고 격자 스냅 토글을 배치 캔버스 상태줄로 옮겼다.
- 구조 패널을 ①평면도 → ②축척 → ③벽 그리기 순서로 재배치했다.
  자동 인식·OCR과 샘플 구조는 접힌 섹션으로 옮겼다.
- 자동 검증: `npm run lint`, `npm run test:run`, `npm run build` 통과.
  스텝 전환, 메뉴 열기·닫기, 기록 핀 보존, 구형 JSON 오류 처리를 테스트한다.
- 사용자 수용시험: **대기**. 기준은 "처음 여는 사람이 순서를 화면만 보고 아는가"다.

## 2026-10-23 오프라인 3D·배치 오류 수정과 E2E

- 3D 조명 환경맵(`lebombo_1k.hdr`, CC0)을 앱에 포함했다. 이전에는 drei
  `preset="apartment"`가 외부 CDN에서 받아, 네트워크가 없으면 3D 화면 전체가
  오류로 바뀌었다. 외부 접속이 막힌 환경에서 production 빌드로 확인했다.
- 84㎡ 샘플에서 새 가구 기본 위치가 L자 거실의 무게중심이라 침대가 내부 벽을
  가로질러 바로 `추가`가 거절되던 문제를 고쳤다. 무게중심에 들어가지 않으면 벽에서
  먼 내부 지점부터 들어가는 곳을 찾는다. 카탈로그 전 품목으로 테스트한다.
- 배치안 전환과 프로젝트 열기(새로 고침 복원 포함) 때 구조 검토 결과를 다시 계산한다.
  이전에는 이전 구조의 경고가 패널과 캔버스에 남았다.
- npm audit 11건(중간 5, 높음 6)을 package.json 범위 안의 패치 업데이트로 해소했다.
- Playwright E2E 4개를 추가했다. `npm run test:e2e`가 production 빌드를 띄워
  실행한다.
- 탭을 숨기거나 닫을 때 바로 저장한다. 이전에는 5초 간격 저장만 있어 닫기 직전 편집이
  사라졌다(E2E에서 3/3 재현). 진행 중인 저장을 기다리지 않고 바로 쓰며, `saveProject`가
  트랜잭션을 명시적으로 commit해 페이지가 사라져도 쓰기가 남는다. commit 없이는 병렬
  부하에서 10회 중 5회 유실됐고, 적용 후 60회 모두 유지됐다. 복원이 끝나기 전에는
  저장하지 않아 빈 기본 프로젝트가 저장되지 않는다.

## 2026-10-23 문·창문 세부 기능 복원

Project v2 전환 때 문 데이터(종류·경첩·열림 방향·각도)는 옮겼지만 화면에서 쓰지 않아
모든 문이 평평한 판으로만 보였다. 2월 단일 방 편집기의 기능을 다중 벽 구조로 옮겼다.

- 구조 속성에서 문 종류, 경첩 위치, 열리는 쪽, 열림 각도(0~180°), 미닫이 방향을 고친다.
- 2D에 문짝과 열림 범위 호, 미닫이문의 문짝과 미는 방향 화살표를 그린다.
- 3D 문짝이 경첩 기준으로 열리고, 문·미닫이문·창문(두 짝 미닫이)을 클릭해 여닫는다.
- 경첩·열림 방향 계산을 `domain/structure/doorGeometry.ts`로 모아 2D와 3D가 같이 쓴다.
  구형 LayoutDoc을 변환한 문은 4개 벽 × 경첩 2 × 방향 2 × 각도 2의 32가지 경우 모두
  예전 단일 방 편집기와 같은 경첩 위치·열림 방향이 되는지 테스트한다.
- 가구 배치 단계의 북·동·남·서 문·창문 추가를 없앴다. 구형 상태에만 들어가 화면에
  그려지지도, 프로젝트에 저장되지도 않았다. 대신 집 구조의 문 도구로 안내한다.
- 벽을 그리는 중 화면이 다시 맞춰지던 문제를 고쳤다. 첫 벽 뒤 인스펙터가 길어져 캔버스가
  커지면 자동 맞춤이 다시 실행되어 확대율이 바뀌고 이어지는 클릭 위치가 어긋났다.
  가구 배치·공간 기록 캔버스도 같은 이유로 사용자의 확대·이동이 초기화됐다.
- 어디에서도 쓰지 않던 구형 단일 방 2D·3D 파일 10개(약 1,900줄)를 지웠다.
  `scene3d/scene3dMath.ts`의 문-가구 충돌 계산은 문 열림 간섭 표시에 쓰려고 남겼다.

## 수동 화면 검증 상태

2026-08-05에는 개발 서버에서 평면도 가져오기, 후보 검토, 작업 공간 전환, 3D,
시나리오, 사진 복원, 로컬 프로젝트와 패키지 생성을 확인했다.

2026-08-06 정합성 수정 이후에는 자동 검증을 다시 통과했지만, 새 브라우저 프로필을
사용한 전체 UI 회귀 검증은 아직 다시 수행하지 않았다. 따라서 다음 항목은 출시 전
수동 스모크 테스트로 남긴다.

1. 서로 다른 구조 리비전을 가진 배치안에서 활성 배치 삭제
2. 편집 직후 새 프로젝트·다른 프로젝트·패키지 가져오기 후 이전 프로젝트 복원
3. 단독 사진과 공유 사진이 연결된 기록 핀 삭제
4. 구형 LayoutDoc JSON 가져오기 후 벽·문·창문·가구 확인
5. `Ctrl/Cmd + S` 패키지 다운로드와 새 브라우저에서 복원

2026-10-23부터 1번과 3번 중 단독 사진 삭제, 5번 중 메뉴로 내보낸 패키지를 같은
브라우저에서 다시 여는 경우는 E2E가 자동으로 확인한다. 2번, 공유 사진, 구형 JSON,
`Ctrl/Cmd + S`, 새 브라우저 프로필 복원은 여전히 수동 확인이 필요하다.

## 출시 전 외부 수용시험

- 사용 허가가 확보된 실제 부동산 평면도 10~20개로 인식 지표 측정
- 84㎡급 평면도 수동 추적 20분 이내 여부를 신규 사용자 3명 이상으로 측정
- 지원 유형별 외벽·내벽·개구부 precision/recall 목표 확정
- 주요 2D/3D 시각 회귀 구축과 E2E의 CI 자동 실행
- 키보드 접근성, 모바일 사용성, PWA 또는 데스크톱 배포 형태 결정
- 대용량 사진 프로젝트의 장시간 저장·용량 초과·백업 복구 훈련

이 시험이 끝나기 전에는 “모든 부동산 평면도를 자동으로 정확히 변환한다”는 표현을
사용하지 않는다. 남은 작업은 [`../todo.md`](../todo.md)에서 관리한다.
