# 평면도 기반 3D 공간 기록·시뮬레이션 개발 계획

> 최신 구현 결과와 검증 증거는
> [IMPLEMENTATION_STATUS.md](./IMPLEMENTATION_STATUS.md)에 정리한다.

> 문서 상태: 구현 기준선 v1.0
> 작성일: 2026-08-05
> 최근 정합성 검토: 2026-08-06
> 대상 저장소: `Interior-Simulator`
> 기준: 1인 개발자와 AI 코딩 지원을 가정한 예상 계획이며, 기간은 구현 중 재산정한다.

## 1. 문서 목적

이 문서는 `Interior-Simulator`를 단일 직사각형 방의 가구 배치 도구에서 다음 제품으로
확장하기 위한 구현 기준을 정의한다.

> 부동산 평면도 한 장을 불러와 실제와 유사한 집 구조를 만들고, 사용자가 구조를
> 보정한 뒤 인테리어를 시뮬레이션하거나 사진·메모와 함께 공간을 기록하고 다시
> 둘러볼 수 있는 프로그램

이 문서는 단순한 아이디어 목록이 아니라 다음 작업의 기준으로 사용한다.

- 기능 범위와 우선순위 결정
- 데이터 모델 변경과 기존 파일 마이그레이션
- 단계별 구현 순서와 완료 조건
- 자동 인식 결과와 사용자가 직접 입력한 정보의 구분
- 테스트, 성능, 개인정보 보호 기준

## 2. 제품 목표

### 2.1 핵심 가치

1. **빠른 공간 복원**
   - JPG, PNG, PDF 형태의 아파트 평면도를 불러온다.
   - 평면도에서 벽, 방, 문, 창문 등 기본 구조를 추출한다.
   - 자동 인식이 불완전해도 사용자가 짧은 시간 안에 보정할 수 있어야 한다.

2. **공간 시뮬레이션**
   - 가구와 가전을 배치하고 이동 동선과 공간 점유를 확인한다.
   - 동일한 집 구조에서 여러 배치안 또는 리모델링 안을 비교한다.
   - 2D 편집 결과를 3D에서 즉시 확인한다.

3. **공간 기억**
   - 방이나 특정 위치에 사진, 설명, 치수, 기억을 연결한다.
   - 과거 모습, 현재 모습, 계획 중인 모습을 별도 버전으로 보존한다.
   - 1인칭 시점으로 공간을 다시 둘러볼 수 있게 한다.

### 2.2 목표 정확도

정확도는 한 종류로 표현하지 않고 다음 두 축으로 나눈다.

- **구조 정확도**: 벽의 연결 관계, 방의 형태, 문과 창문의 위치, 주요 치수
- **시각 정확도**: 벽지, 바닥재, 문 색상, 가구, 조명과 같은 외관

치수가 포함된 선명한 평면도와 사용자 보정이 있는 경우 구조적으로 유사한 3D 공간을
만드는 것이 목표다. 평면도에 존재하지 않는 층고, 벽 두께, 창문 높이, 마감재 정보는
추측값으로 숨기지 않고 `기본값` 또는 `확인 필요` 상태로 표시한다.

### 2.3 초기 비목표

다음 항목은 초기 MVP 범위에 포함하지 않는다.

- 건축 허가나 시공에 사용할 수 있는 BIM/CAD 수준의 정밀 모델
- 구조 안전성, 배관, 전기 배선 계산
- 평면도 한 장만으로 실제 마감재와 가구를 완전 자동 복원
- 모든 부동산 평면도 형식에 대한 무보정 100% 자동 인식
- 다층 주택의 계단 및 층간 구조 자동 생성
- 다중 사용자 실시간 공동 편집

## 3. 대표 사용자 흐름

### 3.1 평면도에서 새 집 만들기

1. 사용자가 새 프로젝트를 만든다.
2. 부동산 평면도 이미지 또는 PDF를 업로드한다.
3. 프로그램이 이미지 회전, 기울기, 여백을 보정한다.
4. 사용자가 평면도에 표시된 실제 치수 한 곳을 선택해 축척을 교정한다.
5. 프로그램이 벽, 문, 창문, 방 영역을 후보로 표시한다.
6. 사용자가 후보를 승인하거나 선을 이동·추가·삭제한다.
7. 닫힌 방 영역과 3D 벽·바닥·천장이 자동 생성된다.
8. 사용자가 2D/3D 분할 화면에서 결과를 확인한다.

### 3.2 시뮬레이션하기

1. 확정된 집 구조에서 새 시나리오를 만든다.
2. 가구, 가전, 붙박이 요소를 배치한다.
3. 충돌, 문 열림 범위, 통행 가능 폭을 확인한다.
4. 시나리오를 복제해 다른 배치안을 만든다.
5. 두 배치안을 전환하거나 나란히 비교한다.

### 3.3 공간 기억 남기기

1. 방 또는 2D/3D 위치에 기록 핀을 추가한다.
2. 사진, 텍스트 메모, 치수, 촬영 방향을 저장한다.
3. 해당 집의 과거·현재 상태를 스냅샷으로 남긴다.
4. 나중에 프로젝트를 열고 1인칭 시점으로 둘러본다.

## 4. 2026-08-05 이전 코드 기준선

이 절은 확장 작업 전의 LayoutDoc v1.x 구조를 기록한 역사적 기준선이다. 현재 구현
상태는 `IMPLEMENTATION_STATUS.md`와 README를 따른다.

현재 구현에서 재사용할 기반은 다음과 같다.

- React 19, TypeScript, Vite
- Zustand 기반 상태 관리와 실행 취소/다시 실행
- Konva 기반 2D 편집 화면
- React Three Fiber 기반 3D 화면
- 가구, 가전, 설비 객체와 2D/3D 동기화
- 문과 창문 편집 및 벽 개구부 렌더링
- Zod 기반 JSON 검증과 버전 마이그레이션
- 자동 저장, JSON 가져오기/내보내기
- 기하, 스냅, 개구부, 스토어 단위 테스트

현재 구조의 핵심 제약은 다음과 같다.

- `LayoutDoc`에 `room` 하나만 존재한다.
- 방은 `width`와 `height`로 표현되는 직사각형이다.
- 문과 창문은 벽 ID가 아니라 `north/east/south/west`에 연결된다.
- 내부 벽, 다중 방, 복도, 발코니, 비정형 외곽선을 표현할 수 없다.
- 평면도 원본 이미지, 축척, 인식 결과, 사용자 보정 이력이 없다.
- 이미지와 사진을 보관하기에는 LocalStorage와 단일 JSON만으로 부족하다.

따라서 자동 인식 기능보다 먼저 공간 데이터 모델을 변경해야 한다.

## 5. 목표 데이터 구조

### 5.1 설계 원칙

- 모든 실제 치수는 내부적으로 밀리미터(`mm`)를 사용한다.
- 2D 구조 모델을 단일 원본으로 삼고 3D 메시는 파생 생성한다.
- 벽은 방향 이름이 아니라 두 점으로 연결된 선분과 고유 ID로 표현한다.
- 문과 창문은 벽 ID와 벽 시작점으로부터의 거리로 표현한다.
- 자동 생성 결과와 사용자 확정 결과를 구분한다.
- 집 구조와 시뮬레이션 시나리오를 분리한다.
- 원본 평면도와 최초 자동 생성 결과는 언제든 복원할 수 있어야 한다.

### 5.2 주요 엔터티 초안

```ts
type Vec2 = {
  x: number;
  y: number;
};

type SourceInfo = {
  origin: "detected" | "manual" | "default";
  confidence?: number;
  confirmedByUser: boolean;
};

type Wall = {
  id: string;
  start: Vec2;
  end: Vec2;
  thickness: number;
  height: number;
  kind: "exterior" | "interior" | "partition";
  source: SourceInfo;
};

type RoomRegion = {
  id: string;
  name: string;
  polygon: Vec2[];
  wallIds: string[];
  usage?: "living" | "bedroom" | "kitchen" | "bathroom" | "balcony" | "other";
};

type Opening = {
  id: string;
  kind: "door" | "window" | "passage";
  wallId: string;
  offset: number;
  width: number;
  height: number;
  sillHeight: number;
  source: SourceInfo;
};

type FloorStructure = {
  id: string;
  name: string;
  elevation: number;
  ceilingHeight: number;
  walls: Wall[];
  rooms: RoomRegion[];
  openings: Opening[];
};

type FloorPlanSource = {
  id: string;
  fileName: string;
  mimeType: string;
  assetId: string;
  opacity: number;
  transform: {
    x: number;
    y: number;
    rotation: number;
    scaleMmPerPixel: number;
  };
  calibrationAnchors: Array<{
    startPixel: Vec2;
    endPixel: Vec2;
    realLengthMm: number;
  }>;
};

type Scenario = {
  id: string;
  name: string;
  structureRevisionId: string;
  furniture: FurnitureItem[];
  materials: MaterialAssignment[];
  createdAt: string;
  updatedAt: string;
};

type MemoryPin = {
  id: string;
  roomId?: string;
  position: Vec2;
  cameraDirection?: number;
  title: string;
  note: string;
  assetIds: string[];
  capturedAt?: string;
};

type InteriorProject = {
  version: "2.0.0";
  id: string;
  name: string;
  sources: FloorPlanSource[];
  structureRevisions: StructureRevision[];
  activeStructureRevisionId: string;
  scenarios: Scenario[];
  activeScenarioId: string;
  memoryPins: MemoryPin[];
  meta: {
    createdAt: string;
    updatedAt: string;
  };
};
```

실제 구현 시 타입을 한 파일에 몰아넣지 않고 `domain/structure`, `domain/scenario`,
`domain/memory`, `domain/import`로 분리한다.

### 5.3 구조와 시나리오의 분리

하나의 프로젝트에는 집 구조가 하나 이상 존재할 수 있고, 각 구조 리비전에는 여러
시나리오가 연결될 수 있다.

```text
Project
├─ Floor plan sources
├─ Structure revisions
│  ├─ Original detection
│  └─ User-corrected structure
├─ Scenarios
│  ├─ Current home
│  ├─ Furniture plan A
│  └─ Remodeling plan B
└─ Memory pins and media
```

가구를 옮기는 작업이 벽 구조의 리비전을 만들면 안 된다. 반대로 벽을 이동해 구조가
바뀌었을 때는 해당 구조를 참조하는 시나리오의 가구 충돌을 다시 검사해야 한다.

## 6. 목표 시스템 구성

### 6.1 프런트엔드

- **Project shell**: 프로젝트 생성, 열기, 복제, 삭제
- **Import workspace**: 이미지/PDF 업로드, 전처리, 축척 보정
- **Structure editor**: 벽 그래프, 방 영역, 문·창문 편집
- **Scenario editor**: 가구, 마감재, 배치안 관리
- **Memory workspace**: 사진, 메모, 위치 핀, 시점 저장
- **2D renderer**: Konva 기반 원본 평면도 오버레이와 벡터 편집
- **3D renderer**: 벽 그래프에서 파생된 바닥, 벽, 개구부 메시 생성
- **Persistence**: 구조화 데이터와 미디어를 분리 저장

### 6.2 로컬 우선 저장

집 평면도와 실내 사진은 민감한 개인정보일 수 있으므로 기본 동작은 로컬 우선으로 한다.

- 프로젝트 메타데이터와 구조 데이터: IndexedDB
- 원본 평면도와 사진: IndexedDB Blob 저장
- 자동 복구: 마지막 정상 저장본과 직전 리비전 유지
- 내보내기: 구조 JSON과 미디어를 포함한 단일 프로젝트 패키지
- 향후 클라우드 동기화: 명시적 사용자 동의가 있는 선택 기능

초기에는 `.interior-project` 패키지를 권장한다. 압축 내부에는
`project.json`, `sources/`, `photos/`, `thumbnails/`를 둔다.

### 6.3 이미지 분석 실행 위치

MVP의 수동 추적은 브라우저 안에서 처리한다. 반자동 인식은 다음 순서로 확장한다.

1. Web Worker 기반 브라우저 이미지 전처리
2. OpenCV.js 또는 동등한 도구를 이용한 선·윤곽 후보 추출
3. 브라우저 실행이 어려운 모델이 필요할 때만 선택적 로컬/서버 추론 서비스 도입

자동 인식 서버를 도입하더라도 원본 평면도를 외부로 전송하는지 사용자에게 명확히
알리고, 로컬 처리 옵션을 우선 제공한다.

## 7. 기능 요구사항

### 7.1 평면도 가져오기

- `IMP-01`: JPG, PNG를 불러올 수 있다.
- `IMP-02`: PDF의 대상 페이지를 선택해 이미지로 변환할 수 있다.
- `IMP-03`: 회전, 자르기, 기울기 보정, 대비 조정을 제공한다.
- `IMP-04`: 두 점과 실제 길이 입력으로 축척을 계산한다.
- `IMP-05`: 원본 이미지를 잠금, 숨김, 투명도 조절할 수 있다.
- `IMP-06`: 원본 이미지와 변환 정보를 프로젝트에 보존한다.

### 7.2 구조 편집

- `GEO-01`: 벽을 클릭 또는 드래그로 생성한다.
- `GEO-02`: 벽 끝점을 이동하고 인접 벽에 스냅한다.
- `GEO-03`: 벽을 분할, 연결, 연장, 삭제할 수 있다.
- `GEO-04`: 수평·수직·각도 스냅과 치수 직접 입력을 지원한다.
- `GEO-05`: 닫힌 벽 그래프에서 방 영역을 계산한다.
- `GEO-06`: 방 이름과 용도를 지정한다.
- `GEO-07`: 벽 두께와 높이를 개별 또는 일괄 변경한다.
- `GEO-08`: 문, 창문, 통로를 특정 벽에 배치한다.
- `GEO-09`: 벽 이동 시 개구부 위치를 유지하거나 경고한다.
- `GEO-10`: 열린 경계, 중복 벽, 짧은 벽, 교차 오류를 표시한다.

### 7.3 자동·반자동 인식

- `DET-01`: 벽 후보를 선분 또는 영역으로 추출한다.
- `DET-02`: 가까운 선분을 연결하고 직교 벽을 정규화한다.
- `DET-03`: 문, 창문, 방 이름 후보를 표시한다.
- `DET-04`: 각 후보에 신뢰도를 기록한다.
- `DET-05`: 낮은 신뢰도 항목을 검토 목록에 모은다.
- `DET-06`: 사용자의 승인 전에는 자동 인식 결과를 확정 구조로 취급하지 않는다.
- `DET-07`: 자동 인식을 다시 실행해도 기존 사용자 수정을 임의로 덮어쓰지 않는다.

### 7.4 3D 생성과 탐색

- `3D-01`: 벽 선분, 두께, 높이에서 벽 메시를 생성한다.
- `3D-02`: 방 폴리곤에서 바닥과 천장을 생성한다.
- `3D-03`: 문과 창문 위치에 개구부를 만든다.
- `3D-04`: 구조 편집 결과를 3D에 즉시 반영한다.
- `3D-05`: 전체 조망과 1인칭 둘러보기 모드를 제공한다.
- `3D-06`: 문 통과, 벽 관통 방지와 기본 이동 충돌을 처리한다.
- `3D-07`: 저장된 카메라 위치로 이동할 수 있다.

### 7.5 시뮬레이션

- `SIM-01`: 동일한 구조에 여러 시나리오를 생성·복제한다.
- `SIM-02`: 가구, 가전, 설비를 배치·회전·복제·잠금한다.
- `SIM-03`: 객체 간 충돌과 벽 바깥 배치를 표시한다.
- `SIM-04`: 문 열림 범위와 가구의 간섭을 표시한다.
- `SIM-05`: 통행 폭 또는 이동 가능 영역을 선택적으로 시각화한다.
- `SIM-06`: 시나리오 A/B를 빠르게 전환하거나 비교한다.
- `SIM-07`: 구조 변경 후 유효하지 않은 객체를 검토 목록에 표시한다.

### 7.6 공간 기록

- `MEM-01`: 방 또는 임의 위치에 기록 핀을 추가한다.
- `MEM-02`: 핀에 텍스트, 사진, 촬영 날짜를 저장한다.
- `MEM-03`: 사진의 촬영 방향을 2D와 3D에 표시한다.
- `MEM-04`: 특정 카메라 위치와 방향을 장면으로 저장한다.
- `MEM-05`: 과거·현재·계획 상태를 이름 있는 스냅샷으로 보존한다.
- `MEM-06`: 방 이름, 기록 핀, 메모 내용으로 검색한다.

## 8. 단계별 개발 계획

## Phase 0. 기준선 안정화와 설계 확정

예상 기간: 1주

### 목표

현재 미커밋 변경을 정리하고 데이터 모델 전환 전의 정상 기준선을 만든다.

### 작업

- 기존 변경사항의 목적과 동작을 검토해 별도 커밋으로 정리
- `npm run build`, `npm run lint`, `npm run test:run` 기준선 확보
- 현재 v1.1/v1.2 JSON 샘플과 회귀 테스트 추가
- v2 프로젝트 스키마와 마이그레이션 정책 확정
- 실제 평면도 테스트 샘플 10~20개 준비
  - 치수 포함/미포함
  - 흑백/컬러
  - 선명한 이미지/압축 이미지
  - 문 기호가 다른 평면도

### 완료 조건

- 현재 기능의 빌드와 테스트 상태가 기록되어 있다.
- 기존 저장 파일을 잃지 않는 마이그레이션 테스트가 있다.
- Phase 1에서 사용할 타입과 좌표계 결정이 문서화되어 있다.

## Phase 1. 다중 벽·다중 방 구조 코어

예상 기간: 2주

### 목표

단일 `Room` 모델을 벽 그래프와 방 영역 모델로 교체한다.

### 작업

- `Wall`, `RoomRegion`, `Opening`, `FloorStructure` 타입과 Zod 스키마 추가
- `north/east/south/west` 기반 문·창문을 `wallId + offset` 방식으로 변경
- 벽 교차, 연결, 분할, 길이, 법선 방향 기하 유틸리티 구현
- 닫힌 벽 그래프에서 방 폴리곤을 찾는 로직 구현
- 기존 직사각형 방을 4개 벽과 1개 방으로 변환하는 v1 → v2 마이그레이션
- 구조 편집용 Zustand slice와 구조 전용 history 구성

### 완료 조건

- 직사각형, L자형, 다중 방 샘플이 데이터로 표현된다.
- 연결된 벽을 이동해도 유효한 벽 그래프가 유지된다.
- 기존 JSON을 v2로 불러온 뒤 동일한 방과 가구가 표시된다.
- 핵심 기하 로직에 결정적 단위 테스트가 있다.

## Phase 2. 평면도 오버레이와 수동 추적 편집기

예상 기간: 2주

### 목표

자동 인식이 없어도 사용자가 평면도를 따라 실제와 유사한 구조를 만들 수 있게 한다.

### 작업

- JPG/PNG 업로드와 캔버스 배경 레이어 구현
- 배경 이미지 이동, 회전, 투명도, 잠금 기능 구현
- 두 점 거리 기반 축척 교정 도구 구현
- 벽 그리기, 연속 벽 그리기, 선택, 이동, 분할, 삭제 도구 구현
- 끝점, 교차점, 수평·수직, 각도 스냅 구현
- 치수 라벨과 직접 수치 입력 구현
- 구조 오류 검토 패널 구현
- 사용성 테스트용 샘플 평면도 3개를 수동 추적

### 완료 조건

- 사용자가 코드를 수정하지 않고 일반 아파트 평면도를 추적할 수 있다.
- 축척을 지정한 뒤 주요 벽 길이 오차를 직접 확인·보정할 수 있다.
- 잘못 연결된 벽과 닫히지 않은 방을 UI에서 찾을 수 있다.
- 84㎡급 일반 평면도를 20분 이내에 기본 구조로 옮길 수 있다.

## Phase 3. 일반화된 3D 공간 생성

예상 기간: 2주

### 목표

어떤 유효한 2D 벽 그래프라도 3D 집 구조로 변환한다.

### 작업

- 기존 `RoomMesh`의 4면 전제를 제거
- 각 벽 선분에서 두께가 있는 3D 벽 생성
- 방 폴리곤 삼각분할 후 바닥과 천장 생성
- `wallId` 기반 문·창문 개구부와 메시 배치
- 내부·외부 면의 재질과 벽 방향 처리
- 방 단위 표시/숨김과 카메라 맞춤
- 복잡한 평면도에서 메시 재생성 성능 측정

### 완료 조건

- 직사각형, L자형, 복도 포함 다중 방이 2D와 3D에서 일치한다.
- 문과 창문이 연결된 벽을 이동해도 올바른 위치에 유지된다.
- 벽의 틈, 겹침, 뒤집힌 면이 테스트 샘플에서 보이지 않는다.
- 일반 아파트 규모의 구조 편집이 눈에 띄는 장시간 멈춤 없이 반영된다.

## Phase 4. 프로젝트 저장과 시나리오

예상 기간: 2주

### 목표

하나의 집 구조에서 여러 배치안을 안전하게 저장하고 비교한다.

### 작업

- `InteriorProject v2.0.0` 저장 구조 구현
- IndexedDB 기반 프로젝트 및 Blob 저장소 구현
- 구조 리비전 생성, 이름 변경, 복원
- 시나리오 생성, 복제, 삭제, 전환
- 구조와 시나리오의 undo/redo 범위 분리
- 프로젝트 패키지 가져오기/내보내기
- 구조 변경 후 가구 충돌 재검사

### 완료 조건

- 앱을 종료한 후에도 원본 평면도, 구조, 가구가 복원된다.
- 하나의 구조에 배치안 A/B를 만들고 독립적으로 수정할 수 있다.
- 원본 자동 생성본 또는 수동 추적본으로 되돌아갈 수 있다.
- 현재 v1.x JSON을 가져와 새 프로젝트로 저장할 수 있다.

### MVP 1 완료 기준

Phase 0~4가 완료되면 자동 인식 없이도 다음 전체 흐름이 가능해야 한다.

> 평면도 업로드 → 축척 설정 → 벽 추적 → 문·창문 보정 → 3D 생성 →
> 가구 배치 → 여러 시나리오 저장

## Phase 5. 공간 기억과 1인칭 방문

예상 기간: 2주

### 목표

시뮬레이터를 실제 공간의 기록과 회상 도구로 확장한다.

### 작업

- 1인칭 카메라, 키보드/마우스 이동, 벽 충돌 구현
- 기록 핀 생성과 방/좌표 연결
- 사진 첨부, 썸네일 생성, 원본 보기
- 촬영 방향과 저장된 카메라 시점 구현
- 상태 스냅샷과 타임라인 기본 UI 구현
- 기록 검색과 방별 필터 구현

### 완료 조건

- 저장된 집 내부를 1인칭으로 돌아다닐 수 있다.
- 사진 핀을 선택하면 관련 위치와 촬영 방향을 확인할 수 있다.
- 과거 모습과 현재 또는 계획 시나리오를 구분해 열 수 있다.

## Phase 6. 반자동 평면도 인식

예상 기간: 3~4주

### 목표

사용자가 모든 벽을 그리지 않아도 검토와 보정 중심으로 구조를 만들게 한다.

### 작업

- 이미지 자르기, 기울기, 이진화, 노이즈 제거
- 긴 직선과 벽 두께 후보 검출
- 근접 선분 병합과 직교 스냅
- 닫힌 영역 및 방 후보 계산
- 문호(door arc), 창문, 방 이름 후보 탐색
- OCR로 치수와 방 이름 후보 추출
- 신뢰도 표시와 항목별 승인/거절 UI
- 자동 결과와 기존 사용자 수정의 3-way 비교
- 평면도 샘플별 인식 지표 수집

### 완료 조건

- 선명한 테스트 평면도에서 주요 외벽과 내부 벽 후보가 생성된다.
- 사용자가 자동 결과를 항목별로 승인·수정할 수 있다.
- 낮은 신뢰도 항목을 프로그램이 확정값처럼 표시하지 않는다.
- 재실행 또는 옵션 변경이 사용자 확정 데이터를 덮어쓰지 않는다.
- 수동 추적보다 구조 작성 시간이 유의미하게 줄어든다.

## Phase 7. 자동 인식 고도화와 제품화

예상 기간: 2~4주 이후 반복

### 목표

다양한 부동산 평면도에서 초기 골격 생성 성공률과 제품 완성도를 높인다.

### 작업

- 실패 사례를 유형별 데이터셋으로 축적
- 기호 탐지 또는 세그멘테이션 모델 도입 필요성 평가
- 규칙 기반 결과와 모델 결과를 결합
- 발코니, 붙박이장, 욕실 설비 등 후보 인식 확대
- 대용량 프로젝트 성능 최적화
- 접근성, 온보딩, 오류 복구, 빈 상태 UI 개선
- 프로젝트 백업과 선택적 동기화 검토
- 데스크톱 패키징 또는 PWA 오프라인 지원 검토

### 완료 조건

- 지원한다고 명시한 평면도 유형에 대해 반복 가능한 품질 지표가 있다.
- 실패 시 수동 편집 흐름으로 자연스럽게 전환된다.
- 사용자 데이터의 저장 위치와 외부 전송 여부가 명확하다.

## 12. 테스트 전략

### 12.1 단위 테스트

- 선분 교차, 투영, 벽 두께 offset
- 벽 연결과 끝점 병합
- 닫힌 방 영역 탐색
- 문·창문 offset 및 경계 검증
- v1.x → v2.0.0 마이그레이션
- 구조 리비전과 시나리오 독립성
- 축척 계산과 좌표 변환

### 12.2 통합 테스트

- 평면도 업로드 → 축척 설정 → 벽 추적 → 저장 → 재열기
- 벽 이동 → 방 영역 재계산 → 3D 메시 갱신
- 구조 변경 → 개구부와 가구 유효성 재검사
- 프로젝트 패키지 내보내기 → 새 브라우저에서 가져오기
- 자동 인식 후보 → 사용자 승인 → 확정 구조 전환

### 12.3 E2E 테스트

Playwright 도입 후 다음 핵심 흐름을 자동화한다.

- 새 프로젝트 생성과 이미지 업로드
- 벽 4개를 그려 방 생성
- 문과 창문 배치
- 2D/3D/Split 전환
- 시나리오 복제와 가구 이동
- 사진 핀 생성과 재열기

### 12.4 시각 회귀 테스트

다음 표준 fixture의 2D/3D 스크린샷을 보관한다.

- 직사각형 원룸
- L자형 공간
- 복도가 있는 방 3개 아파트
- 내부 벽에 여러 문이 있는 구조
- 발코니와 큰 창이 있는 구조

## 13. 성능 및 품질 기준

- 일반 아파트 기준 벽 200개, 가구 300개까지 편집 가능해야 한다.
- 드래그 중 전체 3D 메시를 불필요하게 매 프레임 재생성하지 않는다.
- 무거운 이미지 전처리와 인식은 Web Worker에서 수행한다.
- 자동 저장 때문에 편집 입력이 끊기지 않아야 한다.
- 구조 계산 실패 시 마지막 정상 구조를 유지한다.
- 모든 자동 추정값은 출처와 신뢰도를 추적할 수 있어야 한다.
- 사용자 확정 데이터는 자동화 작업보다 높은 우선순위를 가진다.
- 삭제, 재인식, 마이그레이션 전에는 복구 가능한 리비전을 남긴다.

## 14. 주요 위험과 대응

### 평면도마다 표현 방식이 다름

- 대응: 처음부터 모든 형식을 지원한다고 가정하지 않는다.
- 대응: 규칙 기반 검출, 사용자 보정, 향후 모델 기반 검출을 계층화한다.
- 대응: 지원 샘플과 실패 샘플을 별도로 관리한다.

### 평면도에 실제 치수가 없음

- 대응: 사용자가 알고 있는 한 구간의 길이를 입력하도록 한다.
- 대응: 전용면적만으로 세부 길이를 확정하지 않는다.
- 대응: 축척 미확정 상태를 UI에서 명확하게 표시한다.

### 잘못된 자동 인식이 그럴듯하게 보임

- 대응: 신뢰도 색상, 검토 목록, 미확정 상태를 제공한다.
- 대응: 자동 결과를 바로 확정하거나 저장본을 덮어쓰지 않는다.

### 복잡한 벽 그래프에서 방 계산이 실패함

- 대응: 짧은 벽, 중복 벽, 열린 끝점, 자기 교차를 사전 검증한다.
- 대응: 문제 위치를 캔버스에서 직접 강조한다.
- 대응: 항상 수동 폴리곤 지정 경로를 제공한다.

### 이미지와 사진으로 저장 용량이 증가함

- 대응: 원본과 썸네일을 분리하고 IndexedDB에 Blob으로 저장한다.
- 대응: 프로젝트별 사용량과 미디어 정리 기능을 제공한다.
- 대응: 내보내기 패키지에서 원본 포함 여부를 선택하게 한다.

### 기존 기능 회귀

- 대응: v1.x fixture와 마이그레이션 테스트를 Phase 1보다 먼저 만든다.
- 대응: 기존 단일 방 UI는 v2 편집기가 최소 기능을 충족할 때까지 유지한다.

## 15. 의사결정 원칙

기능 우선순위가 충돌할 때 다음 순서로 판단한다.

1. 사용자가 평면도와 구조를 잃지 않는가
2. 구조를 직접 수정하고 복구할 수 있는가
3. 2D와 3D가 같은 모델을 보여주는가
4. 자동화가 실제 작업 시간을 줄이는가
5. 시뮬레이션과 기록 중 어느 한쪽의 데이터를 훼손하지 않는가
6. 시각적 화려함보다 구조의 신뢰성과 편집 가능성이 확보되었는가

## 16. 최종 완료 정의

제품의 첫 번째 정식 버전은 다음 시나리오를 끊김 없이 수행할 수 있을 때 완료로 본다.

1. 사용자가 부동산 평면도를 업로드한다.
2. 프로그램이 기본 벽과 방 후보를 만든다.
3. 사용자가 몇 가지 오류와 실제 치수를 보정한다.
4. 구조적으로 유사한 3D 집이 생성된다.
5. 사용자가 집 내부를 돌아다니며 가구 배치를 시험한다.
6. 여러 시나리오를 비교한다.
7. 사진과 메모를 실제 위치에 기록한다.
8. 앱을 종료한 뒤 다시 열어도 구조, 시나리오, 기록이 모두 복원된다.
9. 자동 인식이 실패해도 수동 편집으로 결과를 완성할 수 있다.
10. 추정값과 사용자 확인값이 구분되어 과도한 정확성을 주장하지 않는다.
